# 产品命名规范

## 一、统一格式

```
{编号} {目的地} · {主题1},{主题2}-{交通方式}{天数}
```

示例：
- `A6 湖北武汉-恩施 · 黄鹤楼,恩施大峡谷-高铁6日`
- `B20 上海 · 天马山公园徒步,韩湘水博园下午茶-1日`
- `R05 内蒙古呼伦贝尔 · 上兴安极北之旅,草原非遗-专列6日`
- `W02 广东广州 · 长隆飞鸟乐园-家庭票`
- `C12 云南丽江 · 雪域温泉,疗养休闲-双飞疗休养6日`

## 二、字段规则

| 字段 | 规则 |
|---|---|
| 编号 | 必须增添自定义编号：自定义编号（类目字母+两位序号，如 R01/Y01/G01/W01）。编号后**不加冒号**，以空格分隔 |
| 目的地 | 国内精确到省+城市；跨城市行程以英文短横线 `-` 连接（湖北武汉-恩施、山东烟台-威海）；多国/多地以 `+` 连接（斯里兰卡+马尔代夫）；直辖市直接用城市名（上海、重庆）；境外用国家名（新西兰、土耳其）；只到省的补省会/具体城市 |
| 分隔符 | 目的地与主题间为 `·`；主题1、主题2之间为英文半角逗号 `,`（不加空格） |
| 交通方式 | 一律放在末尾、天数之前，并以 `-` 引导；词表：双高铁、双飞、四飞、直飞、专列、Citywalk、高铁、火车、游轮、邮轮、大巴、漫步、步行、自行、徒步 |
| 大巴 | 不写，天数前直接加 `-`（如 `-1日`、`-2日`） |
| 疗休养 | C类产品保留「疗休养」字样，紧跟交通方式（如 `-双飞疗休养6日`） |
| 天数 | 半日 / 1日 / 2日 / 5日 / 6日 / 7日…，以行程实际天数为准；API 天数与表内不符时以表内为准 |
| 非行程产品 | 酒店套餐 `{编号} {目的地} · {酒店名}-{N}日`（无交通）；门票 `{编号} {目的地} · {景区}-家庭票`；研学营 `-半日/-1日`；餐秀体验无天数 |

## 三、分类与编号

1. **分类标准执行前必须向用户确认**，可能是（但不限于）：
   - 红黄绿灯：红=爆款/主推、黄=常规、绿=普通可售（业务含义仍以用户确认为准）；
   - ABC 类目（A红色教育 / B工会活动 / C职工疗休养）；
   - 不分类单一大类；
   - **其他标准**——用户怎么定就怎么执行，不擅自假设。
2. 红黄绿灯场景：**空白灯色单独分组（W），不猜不补**。
3. 编号映射：沿用原编号（A/B/C 场景）或自定义（R/Y/G/W 场景，按原表行序组内递增）。
4. **为什么自定义编号**：产品名称经常变动容易乱，定死编号映射方便；源数据编号
   往往不全或有误，不可全信。

## 四、行序规则

1. **排序方式每次都要向用户确认**，不擅自决定。
2. 一般默认：**价格从小到大**排列；没有价格的按**行程周期**从小到大排列
   （半日 < 1日 < 2日 < …）。
3. 同类产品（如 A 类、红灯）内部可能还需子分区排序，子分区标准也需向用户确认，
   例如：**同一产品负责人**、**同一地点**等。
4. 编号跟随产品，不重新编号，与文件名映射保持不变。

## 五、输入形态与数据来源（执行前确认）

### 输入形态

- **Excel 清单**：一行一个产品，各列含名称/部门/灯色/产品编号等；
- **文件夹**：文件夹内每个文件名即产品名称（一般为 pdf / doc / md，
  且这些文件多由其他格式转换而来）。文件夹输入时**逐个文件读取**，
  文件名即产品名，编号可从文件名头部提取（如 `A1-xxx.pdf` → `A1`）；
- **单个 PDF / DOC / MD 文件**。

### 数据来源

来源可能为（不限于此，与用户确认是哪一种或组合）：

- **现有 pdf / doc / excel**：由我自行转换（如 PDF→MD / PDF→HTML）后读取；
- **有产品编号**：需要中旅（ourtour）联网搜索（接口要点见下）；
- **其他来源**：用户指定（如散落的 md 文件、资料包等）；
- 兜底：全部查不到时用表内/文件名现有信息（名称/部门/灯色）命名并汇报。

### ourtour 接口要点

- 详情页 `ourtour.com/zl/ticketDetail?poiId=...` 是 NUXT SPA，抓不到数据；
  详情接口需 AES+RSA 签名，**不要碰**。
- 用明文搜索接口（免鉴权，实测可用）：
  `POST https://pro-api.ourtour.com/openapi/search/product`
  body: `{"keyword":"产品编号或名称","pageNo":1,"pageSize":5}`
- 有用字段：`productName/mainTitle/subTitle`、`journeyDays`、`destinationCityName`、
  `themeName`、`productTagNameList`、`productDepDate`。
- 查询顺序：按编号搜（表内编号可能是「产品编号：xxx」字符串，先正则抽数字）→
  按名称搜（去空白取前 ~30 字符）→ 表内兜底。
- **命中校验（关键坑）**：编号搜索可能命中无关产品（如长隆门票编号搜到
  「广州康莱德酒店」），必须检查返回 productId 是否等于查询编号或 productName
  是否含表内关键字，误匹配弃用。
- 调用间隔 0.3s 防限流；无结果时接口 `data` 为 null，取数要防御式 `.get()`。

## 六、执行流程

1. **判断输入形态**：Excel 清单 / 文件夹（文件名即产品名，遍历文件，编号从文件名头部提取）/ 单个文档。
   - Excel：读取 Sheet1，解析列（A部门、B产品名称、C日期、…、J产品编号）；
     注意表头行位置不固定（可能有带示例值的"填写样例"行），先读前几行确认数据起点；
   - 文件夹：遍历得到 `文件名 -> 产品名` 映射，与 Excel 清单同样对待；
2. 与用户确认四件事：**分类标准、编号格式、排序方式与子分区标准、信息来源**；
3. 分配编号（沿用原编号或按灯色 R/Y/G/W 分组），分组计数校验（R+Y+G+W=总数）；
4. 取详情：读对应 md，或逐条调 ourtour 接口写 `products_info.json`
   （UTF-8；**json.dump 前把 datetime 转 str**）；
5. 拆分/提炼：编号、目的地+交通、主题、天数；
6. 逐条生成新命名写入 names.json（键=编号，值=完整命名）；
7. 写回 Excel：先备份原文件 `.bak` → 新增「编号」「新命名」列（**保留原名称列**）→
   按行写入 → 按确认的排序规则同步执行行排序；
8. 校验：
   - 逐条对照示例复核；编号无遗漏无重复；分组计数正确；
   - **去重校验：确认重新生成的名称没有内容相同的**；若有相同，
     回到原名称和参考文件（md/API 详情）找差异点区分；**做不到就汇报给用户**；
   - 主题以数字结尾时防粘连（如 `船厂1862-1日`）；清理原名称多余空格；
9. **交付提醒（脚本执行完必做）**：向用户说明本脚本的局限性——
   - **AI 概括可能丢失重要活动**；
   - **旅游地点概况可能出错**（短暂停留/顺路经过的地方可能被当成主要景点放进标题）；
   - 最终需**手动验收**。
   - 建议验收方法：把整张表复制到 DeepSeek 问「有逻辑不对的地方吗」，
     它会指出旅行地点和景点不一致之处，可着重验证这些行；
   - 另提醒：**编号会因排序而打乱，乱序属正常**，与文件名映射不变即可。

## 七、并行处理与模型建议

1. 每条命名必须均由 AI 独立处理：**每两个名称开启一个 agent 并行处理**，
   按「编号→名称」两两拆分派发，并行执行后统一回收合并；
2. 建议使用 **deepseek-v4-flash** 模型执行命名任务，效果更佳；
3. 合并回写时仍须执行第四节排序与第六节校验，保证最终一致性。

## 八、工程注意事项

- 全程 UTF-8，避免 PowerShell 命令行传中文（乱码），用脚本文件 + Read 工具核对；
  不要用 PowerShell Get-Content 核对中文；
- 写表前备份原文件（.bak），改坏可还原；校验失败就回滚重跑；
- 交通/天数信息以 现有名称为基准，不臆改主题内容；
- 同名区分：同目的地多个产品靠主题区分，对照副标题/标签找差异点；
- 门票/自助餐类 API 目的地常为「全国」，真实目的地以表内名称判断；
- 文件夹输入时文件名即产品名，注意清理文件名多余空格/括号标注，
  编号优先从文件名头部提取（如 `A1-xxx.pdf`）。

## 九、真实脚本（实战代码）

- `scripts/ourtour_fetch.py` — 读 Excel → 按红黄绿灯分配编号(R/Y/G/W) →
  逐条调搜索接口抓详情（含命中校验）→ 写 `products_info.json`。
  用法：`python scripts/ourtour_fetch.py --excel 清单.xlsx --out products_info.json`
- `scripts/apply_names.py` — 备份 `.bak` → 新增「编号」「新命名」列（保留原名称列）→
  写入 → **去重校验**（相同则提示回源找差异）。
  用法：`python scripts/apply_names.py --excel 清单.xlsx --info products_info.json --names names.json --bak`
- `scripts/pdf2md_all.py` — 批量 PDF→MD 提取（pymupdf）。
- `scripts/names.example.json` — 命名清单示例（键=编号，值=完整命名）。
